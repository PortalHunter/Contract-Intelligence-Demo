# Contract Intelligence — Interactive Public Demo

**[Launch the browser demo](https://portalhunter.github.io/Contract-Intelligence-Demo/)**

A standalone **synthetic contract upload → illustrative flow-down matrix** demonstration for an offline-first government subcontract compliance application.

> **Training only.** Every example PDF, clause excerpt, classification and evidence citation is fictional/simulated. This demo does not produce legally valid flow-down decisions and does not run the private Python application, OCR, or the actual FAR/DFARS regulatory determination engine.

## Run the demo

1. Open the [public demo](https://portalhunter.github.io/Contract-Intelligence-Demo/).
2. Select **Documents**.
3. Download one, two, or all three of the **100-page synthetic contract packages** generated on that page. Each includes a contract-style cover, award information, a table of contents, sections A-J, work packages, pricing/task schedules, acceptance controls and attachments.
4. Upload those exact PDFs using the file chooser or drag-and-drop. File names alone are not trusted: the browser compares SHA-256 fingerprints against the three known sample PDFs.
5. Select **Generate Flow-Down Matrix**.
6. Explore the searchable matrix, inspect fictional evidence and page references, set temporary review flags and export the demonstration CSV.

Alternatively select **Load all three samples** for a faster walkthrough. Each sample contributes three example clause references; with all three loaded, nine example occurrences are grouped into seven clause rows.

The packages use entirely invented agency/contractor names, identifiers, values, work statements and clause examples. They look like formal procurement documents but are unmistakably labeled synthetic training copies on every page. Only the sample PDFs generated by the page are accepted. **Arbitrary PDF analysis is intentionally not supported.** There is no generic text extraction, OCR, clause-date interpretation, or actual FAR/DFARS edition resolution on this public site. The simulated rule mapping is purpose-built for demonstrations and is not legal advice.

## Safety architecture

- The demo is one self-contained file, `public/index.html`, with no remote libraries or server API calls.
- Sample PDF generation, SHA-256 checks, matrix creation, local review flags and CSV export all execute **inside the browser**. There is no request sending file bytes to a server.
- The Content Security Policy disables external network connections, external fonts/images/media, embedding and form submission.
- Selected documents/results are held only in the current browser session. Refreshing clears them.
- There is no account, database, analytics service or persistent contract storage.
- The GitHub Pages workflow deploys **only** `public/index.html`. It runs a publication guard and a dependency-free test of PDF structures, matching, and matrix evidence before deploying.
- **Do not upload confidential, proprietary or actual customer contract files.** This is a publicly hosted demonstration and not a certified environment for contract handling.

The real offline application and its implementation history remain in a separate **private** repository. This public demo is not a fork.

## Develop and verify

The repository has no dependencies required to view the page. Open `public/index.html` in a browser or visit the hosted Pages URL.

To run the dependency-free checks locally with Python and Node.js:

```bash
python scripts/verify_public_demo.py
node scripts/test_browser_demo.cjs
```

## GitHub Pages

The `Publish synthetic demo to GitHub Pages` workflow runs automatically on pushes to `main`, tests changes in pull requests, and can be triggered manually. The Pages publishing source must be set to **GitHub Actions** in repository settings. When a deployment finishes, the live demo is at the link above.

## What this demonstrates vs. the private product

The public page demonstrates the user experience, **not a real contract-compliance engine**. The actual product is a separately operated offline Python application with PDF/DOCX ingestion, local OCR, source-gated candidate rules, human reviews and evidence exports. Its interpretations, robustness and cybersecurity posture require further independent validation before use for real contractual decisions.
